先给结论：这个站从 10 月 5 日第一行配置，到今天每一次改版，都是我一句话、Muse 去干活。

我没为它专门学前端框架。

你照着下面这套流程走，也能搭出一个属于自己的站。

## 为什么要自己搭一个站？

公众号是租来的房子。

算法改一次推荐规则，你的读者就少一半。

自己的站是买下来的房子。

域名是自己的，文章是自己的，读者进来看到的顺序也是自己定的。

我做这个站的初衷就一个：把公众号和 X 上发的东西，沉淀成一个能被搜索、能被引用、能长期长尾巴的地方。

## 第一步：装 Muse

Muse 是 Meta 的个人 AI 助手产品。

它跟聊天机器人不一样的地方在于：每个用户都有一个自己的助手，跑在一台专属的电脑上。

你关掉 App，它还在。

你交代的事，它能接着干。

去哪装？

网页版直接开 muse.ai。

手机去 App Store 或 Google Play 搜 Muse。

Mac 版去 ai.meta.com/muse/download 下载。

装完登录就能用，免费版有额度，付费版额度更多。

注意一个点：目前开放的地区是美国、加拿大、日本。

我装的是 Mac 版和 iOS 版，两个入口聊的是同一个助手。

## 第二步：第一句话怎么说？

很多人卡在第一步：不知道怎么跟 AI 提需求。

我的经验是：别把它当搜索引擎，把它当一个能干活的下属。

第一句话我给的是目标，不是做法。

我要一个个人知识库网站。

内容围绕 AI、投资、产品思考。

要能发文章，要有首页，要能被搜索引擎收录。

剩下的事：用什么框架、怎么部署、目录怎么排，全部交给它定。

这句话很关键。

你给目标，它给方案。

你给方案，它只会照着做，做出来的东西上限就是你自己的认知。

## 第三步：站是怎么长出来的？

10 月 5 日，站初始化。

框架选的是 VitePress。

选它的理由很实际：写文章就是写 Markdown 文件，不用碰数据库，不用管后端。

10 月 6 日，第一批文章上线。

其中一篇就是讲 Muse 自动部署的，算是这个站的出生证明。

站的结构长这样：

首页是文章流和技能商店的入口。

文章按 AI、投资、工作流这些栏目分。

技能商店是后来长出来的独立栏目，现在有 22 个技能。

每个技能一张卡片，点进去是详情页。

详情页能复制全文，能下载 ZIP，能看演示视频。

## 第四步：上线，域名和部署

站搭在本地不算数，能被别人打开才算数。

我的部署链路是三段：

第一段，代码推到 GitHub 仓库。

第二段，Cloudflare Pages 监听到推送，自动构建。

第三段，构建成功后，绑定到 promangofund.com 这个域名。

构建命令是一条链：先打补丁，再打包技能，再生成 SEO 文件，再跑 VitePress 构建，最后跑两道检查。

其中最后一道检查叫 check-seo，专门拦低级错误。

比如首页缺了按钮、技能顺序乱了、分享图路径错了，构建直接失败，不部署。

这道门禁后来救过我很多次，也坑过我一次，后面讲。

域名是 10 月 12 日迁过来的。

之前用的是 GitHub Pages 的免费地址，迁到自己的域名后，搜索引擎的收录、分享卡片、订阅源全部要跟着切。

切完我逐项验过：sitemap、robots、订阅源、llms.txt、分享图，全部指向新域名。

另外留了一个镜像：GitHub Pages 那边也有一份一模一样的站。

主站挂了，镜像还能看。

两个域名绑的是同一份部署，推一次，两边同时更新。

## 第五步：日常怎么运营？

发一篇文章的流程，我现在已经固定下来了。

写 Markdown，放到对应的栏目目录。

本地构建一次，看有没有报错。

推送到 GitHub。

等 Cloudflare 构建完成。

线上打开文章链接，确认 200，确认图片和视频能播。

这五步缺一步，都不算发完。

本地构建成功不算发完。

推送成功也不算发完。

线上能打开，才算发完。

这个标准是我吃过亏之后定死的。

有一次我构建完就被别的事打断了，没推送。

第二天用户问我文章发到网站了吗，我才发现根本没发。

从那以后，发文章的验收标准就是线上可访问。

改版也是一样的流程。

首页换一张卡片、改一个按钮、换一个技能的顺序，全部走这条链。

小改动也一样，不搞特殊通道。

## 第六步：技能商店是怎么做的？

技能商店是这个站最值钱的部分。

22 个技能，每一个都是我真实在用的工作方法。

比如去 AI 味写作、封面图生成、暖纸水彩插画、浏览器自动化、原理解剖图。

每个技能有三样东西：

一张统一风格的卡图。

一份能直接复制的全文。

一个能下载的 ZIP 包。

后来又加了演示视频。

每个技能一条 30 秒左右的演示片，放在详情页顶部，点开就播。

首页只放 9 个，按编辑推荐顺序排。

目录页放全部 22 个，能按类型和场景筛选，能按推荐、热门、最新排序。

## 第七步：踩过的坑，都是真金白银的教训

第一个坑：构建验收不能只看输出的尾巴。

有一次我连续 4 次部署失败，还在怪平台传播慢。

其实是 check-seo 报了 8 条错误，构建早就失败了。

我本地看构建输出只看了最后两行，错误藏在上面，没看见。

教训：验收必须查退出码，必须看全量错误行。

第二个坑：检查脚本会把你的 UX 决策写成硬断言。

check-seo 里写死了首页必须有复制按钮、技能顺序前 8 名的名单。

后来我把首页按钮改成「点击查看详情」，把一个技能换下首页，构建全挂了。

教训：改产品决策，必须同步改检查脚本里的断言。

第三个坑：推送前不看远端有没有动。

有一次我推送的时候，用户正在用另一个工具改同一个配置文件。

我的旧版本把对方的改动整体覆盖了，5 个技能从配置里消失了。

教训：推送前必先拉远端，动了就先合并再推。

推送后还要逐文件审计 diff，确认没有混进别人的改动。

第四个坑：部署有传播延迟。

新页面上线后 30 到 90 秒内，可能看到旧版或者 404。

这不是坏了，是边缘节点还没同步完。

教训：复查之前先等一分钟，别急着下结论，更别急着回滚。

第五个坑：GitHub 的令牌权限有暗坑。

写 workflow 文件需要令牌额外勾选 Workflows 读写，普通读写权限不够。

这个坑我查了很久，最后结论是：workflow 文件走网页编辑，不走令牌推送。

## 第八步：成本和时间

固定支出只有一个域名。

Cloudflare Pages 免费档够用。

GitHub 免费仓库够用。

Muse 免费额度够日常用，重度使用再考虑付费。

时间成本才是大头。

从 10 月 5 日到今天，站一直在改。

首页改过，归档页改过，技能商店改过三轮，详情页加过视频，按钮换过文案。

每次改动都是几分钟到半小时。

但加起来，就是一个持续进化的站。

## 第九步：照抄清单

如果你也想搭一个，按下面这 10 步走：

1. 装 Muse，网页版开 muse.ai，手机去应用商店，Mac 去官网下载页。
2. 第一句话说目标：我要一个什么样的站，内容是什么，给谁看。
3. 让 Muse 选框架：个人知识库选 VitePress 这类静态站生成器，写文章就是写 Markdown。
4. 定栏目：文章按主题分，技能、项目这类独立内容单独成栏目。
5. 建 GitHub 仓库，代码全部放进去。
6. 接 Cloudflare Pages，监听仓库自动构建。
7. 买域名，绑到 Cloudflare Pages 上。
8. 加一道构建检查：分享图、sitemap、首页关键按钮，缺一个就不部署。
9. 发文章走固定流程：写稿、构建、推送、线上验证，四步缺一不可。
10. 每次改版都先拉远端再推，推完审计 diff，确认没覆盖别人的改动。

## 附：期间用到的技术和平台清单

下面这张表是全过程用到的东西，一个不落。

按层列：

- AI 助手 — Muse（Meta 出品）：全程执行：写代码、跑构建、推送、线上验收、写文章
- 入口 — muse.ai 网页版、iOS App、Mac App：跟助手对话的三个入口，同一个助手
- 静态站框架 — VitePress 1.6.4：把 Markdown 渲染成网站
- 运行环境 — Node.js、npm：跑构建命令
- 内容格式 — Markdown：全部文章和技能文档都用它写
- 前端 — Vue 单文件组件、HTML、CSS：主题组件（技能展示、详情页、归档侧栏）和 custom.css
- 代码托管 — GitHub（mangofund/personal-site）：存全部源码和文章
- 推送工具 — 自研 gh-push.py（走 Git Data API）：不经本地 commit，直接把工作区改动推成提交
- 部署托管 — Cloudflare Pages：监听推送自动构建，绑定 promangofund.com
- 镜像 — GitHub Pages（mangofund.github.io/personal-site）：主站同款备份，推一次两边同时更新
- 域名与解析 — promangofund.com（Cloudflare DNS）：对外地址
- 构建脚本 — patch-vitepress-locale、pack-skills、gen-seo、fix-logo-alt、check-seo：打补丁、打包技能 ZIP、生成 SEO 文件、修 logo alt、构建门禁
- 留言 — Twikoo（主题内置组件）：文章底部留言板
- 统计 — 自研第一方埋点（Cloudflare KV，按北京时间计日活；早期用过 Umami）：看文章和技能的真实访问
- 搜索收录 — Google Search Console、必应站长工具、IndexNow：提交收录、查索引状态
- SEO 文件 — sitemap.xml、feed.xml、JSON-LD、llms.txt、robots.txt：让搜索引擎和 AI 引用读懂这个站
- 技能包 — ZIP 打包（pack-skills.mjs）：每个技能可复制全文、可下载整包
- 视频制作 — HyperFrames（逐帧渲染）、FFmpeg（压 720p）、TTS 旁白：技能演示视频
- 封面与插图 — cover_image_gen（3D 纸雕黏土风）、desk_watercolor（暖纸水彩）、PIL 拼图、Noto Sans SC 字体：技能卡图、文章封面
- 分发渠道 — 微信公众号 PRO的茶里芒果、X @PRO_AI_99T：文章的两个出口
- 本地工具 — Mac、Cursor：我偶尔直接改代码
- 推送授权 — GitHub fine-grained PAT：推送用的令牌；写 workflow 文件要另给权限，改 workflow 走网页编辑
