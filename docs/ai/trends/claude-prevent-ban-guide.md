作者：hello pro（[@PRO_AI_99T](https://x.com/PRO_AI_99T)） · 2026.10.29

前天，我的 Claude 被封了一次号。

封号之后，我把手上的笔记和 X 上的讨论对照着梳理了一遍，整理成这篇教程。

先说清楚边界。Anthropic 没有公开过任何风控打分规则，文中标了"社区经验，非官方"的内容，都是圈子里流传的说法，我没法逐条验证。

写了"我"的部分，是我自己的经历。

这篇文章的主线只有一句话：环境先于付款，稳定先于一切。

## 积分制到底是怎么回事？

> 社区经验，非官方

Claude 的风控是积分制。

注册时，系统先给账号打一个底分。之后你的每个行为都会加分或减分，分数掉到一定程度就直接封号。

据说加分的机会很少，所以底分要在注册时拿好，之后的重点是别扣分。

社区里还有一个关于分数档位的说法。

假设及格线是 60 分，账号掉到 55 分，就会进入观察期。观察期里如果继续扣分，一路掉到 40 分左右，就会直接封号。

观察期最典型的信号是掉登录。有的高权重老号能扛过两三个观察期才被封。

另外，账号寿命本身也算分。社区认为 2023 年的老号权重明显更高，容错率也更大。

下面这张表，是我把笔记里的加减分项整理到一起的版本，全部属于社区经验，非官方。

| 方向 | 行为 |
|------|------|
| 加分或保分 | 手机 App 注册；用 Desktop 客户端；手机端使用；开启记忆；国外实体正规银行信用卡；Google Play；来源干净的官方礼品卡；充值 Credits；账号寿命 |
| 大幅减分 | 频繁换 IP；多设备登录；高并发；反复问同一个问题；频繁登录；刚注册就订 Max；虚拟卡直接绑定；大量使用 Fable；观察期内继续做减分的事 |
| 小幅减分 | 刚注册就订阅；Linux 客户端；多用网页端 |
| 基本无感 | 时区和语言；自称中国人；记忆文件本身；在北京时间的工作时段使用 |

充值 Credits 加分的说法，成本太高，目前没人做过大量实验。Apple Pay 的影响也没人说得清。这两项我都不下结论。

## 注册这一步怎么做？

> 社区经验，非官方

邮箱和 IP 是注册时权重最高的两项。

注册质量差，后面稍微碰一下高危行为就可能直接封号。所以我把注册当成整件事里最重要的一步。

IP 要干净，但不一定要家宽，自建 IP 也可以。

邮箱要自己能控制。接码得来的一次性邮箱不要用。

当然，我自己踩过一个坑。

后来我用一个很老的 Gmail 注册新号，结果直接弹出了身份验证（KYC）。

社区的共识是，注册就弹 KYC 的号直接放弃，所以我把那个号扔了。

社区还有一个说法，Gmail 已经不是最优选，现在更吃香的是其他一些高权重邮箱。

这一点社区里有争议。X 上仍然有人只用 Gmail 活得好好的，也有人用自己的域名邮箱存活。

所以我的做法是，Gmail 可以试，但注册一旦弹 KYC，立刻弃号，不要硬过。

注册本身，建议这样做。

- 用手机 App 注册，社区认为这会加分。
- 如果用电脑注册，给它单独建一个浏览器资料，不要和旧号混用。
- 注册前先把出口检查一遍，下一节会讲怎么检查。
- 注册完先轻度使用，正常聊几句就行，不要立刻付费。

## 支付和订阅怎么走才稳？

> 社区经验，非官方

刚注册就订阅会减分，直接订 Max 会大幅减分。

比较稳的做法是，注册之后隔一两天再订 Pro。X 上多数人同意这个节奏。

也有人认为新号直接付费也行，担心先 Pro 再升 Max 会被"两次支付风控"。这一点我标成待验证，并列放在这里。

我准备照多数人的做法来，先养一两天，再订 Pro，并且只订 Pro。

支付方式的优先级，社区的排序大致是这样。

1. 国外实体正规银行的信用卡
2. Google Play
3. 来源干净的官方礼品卡（要小心黑卡来源）
4. 虚拟卡直接绑定会减分，野鸡虚拟卡更是高危

X 上的高共识是，用美区 Apple ID 在 iOS 官方 App 里内购订 Pro，是优先路径。

原因有两个，一是触发 KYC 的概率更低，二是封号后还能走苹果的退款流程。

礼品卡的余额很难提现，有条件的话可以绑美区 PayPal 走原路退款。

被封号用过的 Apple ID 和支付方式，不要直接绑到新的 Claude 账号上，社区里支付链连坐的报告很多。

一个 Apple ID 只对应一个 Claude 账号。

订阅时如果弹出 KYC，社区的看法是，这说明账号进了考察期，不一定会封。

据说 A 社想先看 KYC 的结果，再决定怎么处置账号。

KYC 用中国护照没有问题，最大的雷是"一人多扫"，也就是同一个人的证件被用来给多个账号过验证。闲鱼上很多现成账号都是这种情况，千万要小心。

护照这一条，X 上有冲突的案例，有人过了之后一两天内还是被封，也有人长期活着。所以过了 KYC 只是进了下一关，不算安全。

## IP 怎么固定住？

> 社区经验，非官方

注册之后，IP 最重要的是稳定。

尽量一直用同一个 IP，最好和注册时的 IP 一致。只要求干净，不要求一定是家宽。

代理一定要开全局并启用 TUN，这是整篇里最需要照做的一条。

我自己在这里踩了两个坑。

第一个坑在共享机场。我用共享机场节点的时候，出口 IP 会在两个地址之间来回跳。

我换了台湾节点之后，Mac 和手机的出口 IP 才对齐。

所以我现在的原则是，Mac 和手机必须使用同一个节点，用之前先看出口。

第二个坑在 Clash 退出。Clash 退出以后，TUN 就失效了，Claude 随即报 503。

我自己的判断是，Claude 的保护逻辑会检查 Clash（mihomo）的 socket TUN 状态。Clash 退出后 socket 不存在，系统就永远判定"没有 VPN"，于是所有请求都被拦成 503。

这是我根据现象做的推断，官方没有说明过。

Claude Code 的 `~/.claude/settings.json` 里，如果 `HTTPS_PROXY` 指向了这个受保护的入口，也会跟着一起失败。

所以 Clash 没跑起来的时候，我不会打开 Claude。

### 全局和 TUN 到底该怎么设？

我的做法分三层。

- 开启 TUN，让系统的所有流量都由 Clash 接管。
- 建一个只有一个节点的策略组，名字叫 ClaudeFixed。
- 把 Claude 和 Anthropic 的域名写死到 ClaudeFixed。

这里有一个细节要说清楚。Clash 里的"全局模式"会跳过规则，所有流量走 GLOBAL 组。如果你的 Verge 开的是规则模式，Claude 的流量会按规则走 ClaudeFixed。如果你切到了全局模式，就要把 GLOBAL 也选成同一个节点。

两种方式都行，关键是 Claude 的最终出口是同一个节点。

ClaudeFixed 里只放这一个节点，不要加其他节点，不要用 url-test、fallback、load-balance 这类自动切换的类型。

这样节点挂了，请求就失败，不会悄悄切到别的国家，更不会回落到国内直连。

另外，TUN 开着的时候，系统代理建议关掉，避免叠层。

### Mac：Clash Verge

下面是一段通用的配置片段，节点名全部是占位符，你需要换成自己订阅里的节点名。

```yaml
proxy-groups:
  - name: ClaudeFixed
    type: select
    proxies:
      - YOUR_FIXED_NODE   # 只放这一个，不要加别的节点

rules:
  # 放在规则列表最前面，要在任何 AI 规则集之前
  - DOMAIN-SUFFIX,anthropic.com,ClaudeFixed
  - DOMAIN-SUFFIX,claude.ai,ClaudeFixed
  - DOMAIN-SUFFIX,claudeusercontent.com,ClaudeFixed
  - DOMAIN-SUFFIX,claude.com,ClaudeFixed
  - DOMAIN-KEYWORD,anthropic,ClaudeFixed
  - DOMAIN-KEYWORD,claude,ClaudeFixed
  # 后面接你原来的规则
```

Verge 里的设置，我是这样调的。

- 打开 TUN。
- 关闭系统代理，避免叠层。
- 模式保持规则，或者切全局并让 GLOBAL 选同一个节点。

订阅更新之后，手改的配置可能被覆盖。建议用 Verge 的覆写功能，或者每次更新后检查一遍 ClaudeFixed 还在不在。

### iPhone：Shadowrocket

Shadowrocket 的写法略有不同，思路一样。

```ini
[Proxy Group]
ClaudeFixed = select,YOUR_FIXED_NODE,policy-select-name=YOUR_FIXED_NODE

[Rule]
# 必须放在 AI 相关规则集之前，否则会被抢走并跳节点
DOMAIN-SUFFIX,anthropic.com,ClaudeFixed
DOMAIN-SUFFIX,claude.ai,ClaudeFixed
DOMAIN-SUFFIX,claudeusercontent.com,ClaudeFixed
DOMAIN-SUFFIX,claude.com,ClaudeFixed
DOMAIN-KEYWORD,anthropic,ClaudeFixed
DOMAIN-KEYWORD,claude,ClaudeFixed
```

导入配置之后，要确认三件事。

- 订阅里的节点名和 ClaudeFixed 里的名字完全一致。更新订阅后节点改了名，这里要同步改。
- 全局路由选"配置"，并且在配置列表里勾选启用它。
- 不要再把 Claude 手动切到某个 url-test 的地区组，那会换 IP。

### 两边怎么对齐？

每次换地方、换设备、打开 Claude 之前，我会做这五步。

1. Mac 上运行 `curl -s https://ipinfo.io`。
2. 手机浏览器打开 `https://ipinfo.io`。
3. 对比两边的 ip 和 org（ASN），必须一致。
4. 不一致，先别开 Claude，去查手机是不是直连了，或者走了别的节点。
5. Clash 挂了，先别开 Claude Code。

org 里如果写着 Hosting，社区建议慎用，尽量选 ISP 或 Residential 类型的出口。

### 登录前还要查什么？

出口对了还不够，泄漏同样会出问题。我会在注册用的浏览器资料里查下面几项。

- 用 browserleaks 之类的网站查 WebRTC，不应出现国内真实 IP。
- DNS 和出口一致，没有运营商 DNS 泄漏。
- IPv6 要么和出口一致，要么关掉，避免旁路。
- Mac 终端运行 `scutil --proxy`，走 TUN 时系统代理通常应该是关闭状态。
- 终端运行 `env | grep -iE 'proxy|anthropic'`，检查有没有残留的 `ANTHROPIC_BASE_URL` 和脏代理。

## 设备和客户端怎么配？

> 社区经验，非官方

多设备登录会大幅扣分，最好一个号只在一台电脑上使用一个客户端。

我给自己定的分工是这样的。

- iPhone 用来注册、订 Pro，以及日常轻度使用。
- Mac 跑 Claude Desktop 和 Claude Code，是主战场。
- 网页端尽量少用，只保留手机端和 Desktop 登录。

Windows 和 macOS 没有区别，Linux 使用会减分。X 上有人实测，同一个 IP 下 Linux 环境秒封，桌面系统能过。

CLI 和 Desktop 都可以用，社区认为 Desktop 略优，会少量加分。

用量上有几条规矩。

- 不要一上来就把周限额用完，尽量平均使用。
- 用量大的人，宁可开两个独立环境的号轮换，也不要在一个号上榨干。
- 控制并发，不要反复问同一个问题。
- 额度看到黄色提示就停。
- 重要的项目放在本地 Git，不要只存在云端会话里。

另外，开启记忆功能据说会加分。时区和语言基本不扣分，社区也有人建议改成台北时间并和出口对齐，两种说法冲突，我先按待验证处理。

跟 Claude 说自己是中国人也没事，社区的说法是不会因为记忆文件就封号。

也别用第三方客户端去接订阅，比如 OpenClaw 这类工具，这是社区公认的高发雷区。

## 进了观察期怎么处置？

> 社区经验，非官方

掉登录是观察期最典型的信号。

如果你发现频繁掉登录，或者反复要求重新授权，就当自己已经进了观察期。

这个阶段的原则很简单，停下一切会减分的事。

- 停止换 IP。
- 停止升档，别升 Max。
- 停止打满额度。
- 停止登录新设备。
- 只保留最低限度的使用。

观察期内再有减分行为，大概率直接封号。

回复突然变短、变"降智"的时候，先去查出口是不是变成了 Hosting，有没有泄漏，别急着开新号。

如果账号被明确封了，我建议这样处理。

1. 能登录就先导出数据，把重要项目备份到本地。
2. 取消续订，走退款。App Store 订阅去 reportaproblem.apple.com，官网订阅走 Refund Request。
3. 登录后提交申诉，写清楚事实、场景、时间和用的客户端。
4. 不要在同一个环境里立刻开新号。

官方的透明度数据被社区反复引用，据说 2026 年上半年封号约 1140 万个，申诉被推翻的比例约一成。这组数字我没有自己核实过，我只拿它来提醒自己，申诉能成功，但别当成保险。

如果是忘了关 VPN 误进了大陆 IP，社区有"旅行误入不支持地区"的申诉解封样本，也没有保证。

## 哪些事绝对不要做？

> 社区经验，非官方

下面这些是我在笔记和 X 上反复看到的高危操作，不管怎么省事，我都不会碰。

- 买闲鱼上的成品账号，或者找人代过 KYC。一人多扫会连坐，有人充值后秒封。
- 用野鸡虚拟卡，或者高危的网页虚拟卡直接绑定。
- 在共享机场里乱切国家节点，或者开着自动切换的策略组。
- 新号直接订 Max。社区认为这是最高危的组合之一。
- 拼车，多个账号共用一张支付卡，或者同一个浏览器资料里登多个号。
- 订阅接到非官方客户端上使用。
- 在会话里做蒸馏、灰产相关的内容，或者反复踩安全护栏。内容通道另有一套审查，环境再干净也没用。
- 在同一个环境里被封之后，立刻开新号硬冲。社区的说法是，使用政策不允许用新号绕过封禁。
- 付费买"代 KYC"、假证件，或者听信"100% 保号"的代开广告。社区里有防封博主自己也被封的例子。
- 把远程海外 Mac 或云主机当成万能解法。它不是银弹，已经有人翻车。

## 一页清单

社区经验，非官方。我把前面所有内容压成了下面这份清单，开号前后打印出来对着勾就行。

**开号前**

- [ ] 旧号残留已经清掉（`~/.claude`、钥匙串、浏览器资料、旧会话），环境变量里没有 `ANTHROPIC_BASE_URL` 和脏代理
- [ ] 被封号用过的 Apple ID 和支付方式，没有绑到新号上
- [ ] 固定一个干净节点，Mac 和手机 `ipinfo.io` 的 ip 与 ASN 一致
- [ ] Clash Verge 开 TUN，ClaudeFixed 里只有一个节点，Claude 域名写死
- [ ] Shadowrocket 的 ClaudeFixed 节点名与订阅一致，规则排在 AI 规则集之前
- [ ] WebRTC、DNS、IPv6 自检通过，`scutil --proxy` 符合预期
- [ ] 自己能控制的邮箱，专用的浏览器资料，或者直接用手机 App 注册

**注册后**

- [ ] 注册没有弹出 KYC，弹了就弃号
- [ ] 轻度使用一到两天，不付费，不开高并发，不多设备来回切
- [ ] 再订 Pro，只订 Pro，不碰 Max
- [ ] 优先用美区 App Store 内购，其次是国外实体信用卡或 Google Play
- [ ] 订阅弹 KYC 就本人真实证件，不代扫

**日常使用**

- [ ] 一个号、一台电脑、一个官方客户端，少用网页
- [ ] 额度看到黄色就停，不要打满周限额
- [ ] Clash 没跑起来，就不要打开 Claude 和 Claude Code
- [ ] 不换节点，不换设备，不接第三方客户端
- [ ] 定期查看 Active sessions，踢掉陌生登录
- [ ] 重要项目放本地 Git

**出现异常**

- [ ] 频繁掉登录，立即进入观察期模式，冻结所有高危操作
- [ ] 回复变短，先查出口有没有变 Hosting 或泄漏
- [ ] 被封后走退款、取消续订和申诉，不要秒开新号

最后说一句。

我的体会是，网络决定账号能活多久，付款渠道决定被封之后你亏多少。

这些做法只能降低封号的概率，没有哪一条能保证不封。如果你发现了新的情况，欢迎来 X 上找我交流，我是 @PRO_AI_99T。
