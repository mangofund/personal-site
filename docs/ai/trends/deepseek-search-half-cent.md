# DeepSeek 搜索一次只要半分钱，推理成本战打到什么程度了

<div class="meta-line">2026.11.16 · AI · 阅读约 10 分钟</div>

<div class="article-cover">

![DeepSeek 搜索一次只要半分钱，推理成本战打到什么程度了](/images/deepseek-search-half-cent-cover.jpg)

</div>

半分钱是真的。

DeepSeek 官方定价页写着，搜索每 1000 次 5 元。

一次就是 0.005 元，半分钱。

但半分钱不是一次联网问答的全部成本。

这篇文章算三笔账。

半分钱到底在为什么付钱。

一次联网问答到底花多少钱。

这个价对做 AI 产品的人意味着什么。

## 半分钱一次，到底在为什么付钱

我们先把时间线拉直。

2026 年 10 月 17 日，DeepSeek 上线两个新接口，Search 和 Fetch。

Search 按 query 搜网页，返回结构化结果。

Fetch 抓单个网页，以 Markdown 格式返回标题和正文。

定价同时公布，每 1000 次成功请求 5 元，约合 0.75 美元。

11 月 1 日零点起正式收费。

此前在 DeepSeek Harness、Claude Code、Codex 里，这两个接口一直免费。

直接调接口从 10 月 17 日上线起就按次收费，11 月 1 日收的是嵌在 Harness 等工具里的服务端调用。

11 月 1 日之后，"隐形的免费午餐"按次收费了。

11 月 13 日晚，DeepSeek 又往前走了一步。

"全家桶应用 API"开放出来。

以前只在官方 App 和网页版里跑的联网搜索、深度思考搜索、文件输入、阅读链接、模型安全、语音识别与语音合成，现在开发者可以直接调用。

这项公告没动模型的价格，动的是账单的结构。

模型 token 费照旧，工具按用量另计。

搜索和网页抓取每千次 5 元，一次合五厘钱。

文件解析与 OCR 每千页 1.5 元。

语音合成每万字符 3 元，语音识别每小时 0.78 元，后两项目前限时五折，分别是 1.5 元与 0.39 元。

语音合成按字符计费，汉字算 2 个，字母、数字和空格算 1 个。中文用户按字数估算，会低估一半。

"DeepSeek 搜索一次半分钱意味着什么"登上头条热榜，就是这件事。

我们先把"一次"这个词拆开。

半分钱的单位是请求次数，不是文章数，不是问题数。

Search 和 Fetch 各按每千次成功请求 5 元计费。

搜索返回五条还是五十条，不改变单次搜索价格。

你要是把五十条结果逐页再抓一遍，那些成功的 Fetch 请求就要另计。

计费的口径写得很直白。

只有返回 HTTP 200 且产生结果的请求才会计费。

请求失败、搜索无结果或超时，都不收钱。

这个"按成功计费"的设计有点讲究。

失败和无结果不收钱，等于把搜索质量的试错成本揽在了自己身上。

模型可以放心大胆地多搜几次，用户只为拿到结果的那次买单。

但单价只是半句话。

什么情况收钱，什么情况不收，才是真正决定月支出的部分。

走联网工具时，搜索实际按调用里的查询词条数计费。

一次调用包含 3 个查询词，就计 3 次。

图片搜索是每张图片计 1 次，模型框选图中区域时每个区域另计 1 次。

阅读链接按成功抓取的网页数计费。

被安全审核替换成"不允许"或"不可用"的页面也在收费之列，只有抓取失败的链接不计费。

深度思考搜索里的"打开网页"只在实际从网络抓取时收钱。

再次打开同一网页、在网页内翻页、打开内容已随搜索结果返回的页面都不计费，页内查找完全免费。

出错的那一侧更值得留意。

回答已开始生成之后出错，比如推理超时，HTTP 状态码已经是 200，失败之前执行的推理、搜索与阅读照常计费。

内容审核拒答时，拒答前已消耗的 Token 同样要收钱。

输入没过审返回 400 时，输入 Token 仍按缓存命中价计费。

文件输入的费用只发生在解析那一次，按文档页数一次性计费，客户端中途断开也不豁免。

这些细则合起来，意思就一个。

单价是半分钱，但一次问答到底付几次半分钱，由模型说了算。

用不用工具由模型自己判断。

一次搜索调用可能包含多个查询词。

这才是算成本的起点。

## 一次联网问答，到底花多少钱

我们先算一笔最普通的账。

一次普通联网问答，用 deepseek-flash，高峰时段。

假设拼入搜索结果的输入约 3 千 token、输出 1 千 token、搜索 3 个查询词。

模型的价格先摆出来。

deepseek-flash 高峰时段，输入缓存未命中 2 元每百万 token，输出 8 元每百万 token。

输入 3000 token，3000 除以 100 万乘以 2 元，等于 0.006 元。

输出 1000 token，1000 除以 100 万乘以 8 元，等于 0.008 元。

Token 费一共 0.014 元。

搜索 3 个查询词，3 乘以 0.005 元，等于 0.015 元。

合计 0.029 元，不到 3 分钱。

这个数和开发者的实测口径在同一个量级。

一次带联网搜索的提问，Token 费加三次搜索约三分钱。

所以"半分钱一次"这个说法，严格讲没错。

但它只覆盖了搜索那一项。

一次问答的真实成本，是 Token 费加工具费。

Token 费那一项，很多人会低估。

因为多步对话里，搜索结果、抓取网页和思考过程都会拼回上下文。

响应里的 usage 是整个请求的计费用量，按各步推理累加。

工具调用得越多，Token 账单同步变大。

深度思考模式下，模型最多调用约 20 次工具后作答。

这既是能力上限，也恰好给单次请求的费用画了个封顶线。

我们算一笔重度检索的账。

一篇重度检索的长文问答若接近 20 次工具调用的上限。

按 10 轮搜索各 3 个查询词、5 次实际抓取估算。

30 次搜索乘以 0.005 元，等于 0.15 元。

5 次抓取乘以 0.005 元，等于 0.025 元。

工具费约 0.18 元。

再加上多轮累加后数倍于普通问答的 Token 费。

这类请求的真实成本通常以"几毛"计，而不是单次单价给人的"五厘"印象。

所以半分钱是单价，不是总价。

总价取决于你的 Agent 一次任务搜几次、抓几页、拖回多少上下文。

这里还有一张价格表，决定 Token 费的高低。

DeepSeek 现在只有两个模型在售。

deepseek-flash，对应 DeepSeek-V4.1-Flash-1017。

deepseek-v4-pro，对应 DeepSeek-V4-Pro-0813。

两个模型上下文都是 1M token，输出最大 384K。

价格差得不少。

flash 高峰时段输入缓存未命中 2 元每百万 token，输出 8 元。

v4-pro 高峰时段输入缓存未命中 9 元，输出 27 元。

空闲时段全部减半。

flash 空闲输入 1 元，输出 4 元。

v4-pro 空闲输入 4.5 元，输出 13.5 元。

高峰时段是北京时间周一至周五 9:00 到 12:00、14:00 到 18:00，不含中国法定节假日。

其余时段，包括周末及法定节假日全天，都是空闲时段。

搜索和抓取的工具费不分峰谷，全天同价。

缓存是另一张牌。

输入命中缓存，价格直接掉一个量级。

flash 空闲时缓存命中输入只要 0.02 元每百万 token，高峰 0.04 元。

v4-pro 空闲时缓存命中输入 0.15 元，高峰 0.30 元。

缓存命中和未命中的价差，flash 是 50 倍，v4-pro 是 30 倍。

同一段系统提示词，反复用就便宜，新写就贵。

Agent 的多轮对话里，前面的上下文一旦进了缓存，后面的轮次输入成本就大幅下降。

但输出永远按全价算。

输出是账单里最硬的那一块。

还有一个限制要说明。

联网工具（deepseek_web_search）目前只支持 flash，v4-pro 还不能用这套工具。

这三张表合起来，才是一次联网问答的完整账单。

搜索半分钱，抓取半分钱，Token 按模型、按时段、按缓存状态另算。

## 为什么 DeepSeek 能定这个价

半分钱这个价，放在全球搜索 API 市场里，是最便宜的一档。

横向看，大约是主流海外方案的一折到两折。

问题来了。

为什么 DeepSeek 能定这个价，别人定不了。

第一个原因，搜索引擎是自研的。

DeepSeek 的 Search 和 Fetch 由自家搜索引擎驱动，不是转售 Google 或 Bing。

转售要付批发价，再加自己的毛利，价格下不来。

自研的边际成本是自己的算力和带宽，没有中间商。

第二个原因，规模摊薄。

DeepSeek 的官方 App 和网页版有海量用户，搜索基础设施本来就在跑。

API 的搜索调用复用同一套系统，新增调用的边际成本很低。

第三个原因，按成功计费的底气。

失败和无结果不收钱，这句话说出来容易，做到需要搜索质量过硬。

如果搜索成功率低，免费的失败调用会把成本吃掉。

DeepSeek 敢这么定，说明它对自己的搜索成功率有信心。

当然，这一点目前还没有第三方数据验证。

DeepSeek 没有公布任何搜索质量指标。

所有判断都只能基于定价本身。

第四个原因，也是最关键的一个，战略意图。

搜索 API 本身赚不了大钱。

一天搜一万次，也才 50 元。

真正的意图在"全家桶"三个字上。

DeepSeek 要做的是 Agent 开发者的默认工具栈。

模型、搜索、抓取、文件解析、语音，全套都在一家。

开发者一旦用顺了，迁移成本就高了。

搜索半分钱，是获客价。

它把开发者圈进来，真正的收入在 Token 费上。

这个打法 DeepSeek 不是第一次用。

模型 API 的定价一直是全球最低一档。

flash 闲时输入缓存未命中 1 元每百万 token，输出 4 元。

DeepSeek 的策略从来不是靠单价赚钱。

而是把推理成本打下来，让更多人用，用量起来之后再从规模里找利润。

搜索 API 是同一套逻辑的延伸。

把联网这道工序也变成白菜价。

还有一个时间点值得注意。

11 月 1 日之前，Harness、Claude Code、Codex 里的搜索调用一直免费。

11 月 1 日之后开始收费。

DeepSeek 先让开发者在 Agent 工具里免费试用，把工作流嵌进去。

等大家离不开的时候，再按次收费。

这个节奏，和模型 API 的免费额度、降价策略是一脉相承的。

先养习惯，再收钱。

## 和竞品比，这个价处在什么位置

我们把价格摆在一起看。

| 搜索 API | 每千次成功请求 |
| --- | --- |
| Tavily | 约 8 美元 |
| Brave Search | 约 5 美元 |
| Google Custom Search | 约 5 美元 |
| Exa（基础档） | 4 美元 |
| Exa（深度档） | 最高 15 美元 |
| Serper | 约 1 美元 |
| DeepSeek | 0.75 美元 |

DeepSeek 是表里最便宜的。

比第二便宜的 Serper 还低 25%。

比 Tavily 低 90% 以上。

这个价差大到什么程度。

一个每天调用一万次搜索的开发者。

用 Tavily，一个月 2400 美元。

用 DeepSeek，一个月 225 美元。

一年下来差 2.6 万美元。

对独立开发者和小团队来说，这不是小钱。

但价格不是唯一的维度。

搜索 API 拼的是两个东西，价格和质量。

价格 DeepSeek 赢了。

质量目前没有公开数据。

DeepSeek 没有公布搜索结果的相关性、覆盖率、时效性指标。

也没有第三方做过横向评测。

便宜的搜索如果结果不准，开发者要多搜几次、多抓几页。

多出来的调用和 Token，反而把省下的钱吃回去。

所以这个价的真正含金量，要等实测数据出来才能定论。

还有一个维度，限速。

Search 每秒 100 次、Fetch 每秒 25 次，按账号计。

Search 的限速比上线初期放宽了二十倍。

另外，搜索接口返回的内容是分层的。

有给前端展示的短摘要，有给模型阅读的长摘要，还有正文。

发布说明称，它会过滤 SEO 作弊、GEO 操纵和低质 AI 内容。

就是希望搜索结果少被那些专门操纵排名和引用的内容占住。

这个过滤做得怎么样，同样没有公开数据。

所以横向比较的结论是两句话。

价格上，DeepSeek 是全球最低一档，没有对手。

质量上，目前是未知数，等实测。

做选型的人，价格可以现在就信，质量要自己测。

## 对做 AI 产品的人，这意味着什么

我们回到最开始的问题。

搜索一次半分钱，对做 AI 产品的人意味着什么。

第一层意思，搜索从成本项变成了可以随便堆的功能。

以前给 Agent 加联网搜索，要算一笔账。

一次任务搜十次，Tavily 就是 8 美分。

一天一万次任务，就是 800 美元。

搜索次数是产品经理要控制的指标。

现在搜索一次半分钱，十次 5 分钱。

一天一万次任务，搜索费 500 元。

搜索不再是需要审批的成本。

产品经理可以放心让模型多搜几次。

这个变化的直接后果，是 Agent 的工作流会变"啰嗦"。

以前为了省钱，宁可少搜一次，靠模型自己的知识硬答。

现在多搜几次的成本忽略不计，宁可多搜，不可少搜。

搜索的调用量会上去。

第二层意思，真正的成本在 Token。

搜索半分钱是明码标价。

Token 费是暗流。

每一次搜索和抓取带回的材料，都会拼进上下文。

上下文越长，下一轮的输入 Token 越多。

输出 Token 也随之变多。

深度思考模式最多 20 次工具调用，这个上限既是能力边界，也是成本封顶线。

做产品的人要盯的指标变了。

不是搜索单价，而是单次任务的工具调用次数和上下文长度。

一个任务搜 3 次和搜 30 次，搜索费只差 0.135 元。

但上下文可能差出几万 Token，Token 费差出一两毛。

第三层意思，商业模式在变。

搜索变成白菜价之后，靠搜索本身赚钱的路就窄了。

价值往上游走，走到模型和工作流上。

DeepSeek 的"全家桶"就是这个逻辑。

开发者用全套，DeepSeek 赚 Token 费。

搜索 API 是钩子，Token 是鱼。

独立开发者的选型逻辑变了。

以前选搜索 API，看价格和质量。

现在价格这一项，DeepSeek 把天花板打穿了。

选型的重点变成，我的 Agent 工作流能不能跑在 DeepSeek 的模型上。

联网工具目前只支持 flash，v4-pro 还不能用。

flash 的能力够不够你的场景，这是比价格更重要的判断。

第四层意思，免费和收费的边界在移动。

DeepSeek 的 App 和网页版，搜索一直是免费的。

API 的搜索从 11 月 1 日开始收费。

这个分野说明了一件事。

面向 C 端用户的搜索，免费是获客手段。

面向开发者的搜索，收费是收入来源。

同一项能力，两种定价。

做产品的人要算清楚，自己在 C 端还是 B 端。

如果你在做面向用户的 AI 搜索产品，DeepSeek 的免费 App 是你的竞品。

如果你在做 Agent 工具，DeepSeek 的 API 是你的供应商。

两个位置，两种打法。

最后给一张检查清单。

如果你正在用 DeepSeek 的搜索 API，或者正准备用。

这几件事值得每周看一次。

单次任务平均调用几次搜索、几次抓取。

单次任务的 Token 消耗是多少，输入和输出各占多少。

缓存命中率是多少，系统提示词有没有复用。

高峰时段的调用占比是多少，能不能挪到空闲时段。

深度思考模式的工具调用，有没有接近 20 次的上限。

这五个数，比"半分钱一次"这个标题更能告诉你，你的成本到底花在哪。

半分钱是真的。

但它只是账单的第一行。

真正的账，在 Token 里，在调用次数里，在上下文的长度里。

推理成本战打到这个程度，拼的是谁能把一次任务的总成本压下来。

而总成本的决定权，越来越多地交到了模型手里。

模型决定搜几次，抓几页，想多久。

人能做的，是把边界划清楚。

哪些任务值得搜，哪些不值得。

搜几次就够，什么时候该停。

这才是半分钱背后，真正值得算的那笔账。
